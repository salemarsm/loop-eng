# loop-eng Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plugin do Claude Code com a skill `loop-eng`: refinamento → contrato → loop autônomo (planejar, implementar por nível de modelo, verificar, consenso de revisores, PR), injeções e quadro espelhado no GitHub Projects.

**Architecture:** A parte determinística (slug, worktree/branch, arquivos de estado, injeção, quadro, sync com GitHub) vira um CLI Node sem dependências (`scripts/loop-eng.mjs`) testado com `node:test`. O julgamento (refinar, classificar injeção, orquestrar subagentes, consenso) fica em prosa: `SKILL.md`, `refinamento.md` e prompts dos subagentes. O SKILL.md chama o CLI para tudo que é mecânico.

**Tech Stack:** Node ≥ 22 (só stdlib: `node:fs`, `node:path`, `node:child_process`, `node:test`, `node:assert`), git, `gh` CLI (Projects v2), Markdown.

**Spec:** `docs/design.md`

## Global Constraints

- Repo `salemarsm/loop-eng`, privado, formato plugin: `.claude-plugin/plugin.json` + `.claude-plugin/marketplace.json` com `"source": "./"`; skill em `skills/loop-eng/`.
- CLI sem dependências npm; roda em Windows (Git Bash/PowerShell) e Unix; caminhos com espaço funcionam.
- Branch do loop `loop/<slug>`, worktree `.claude/worktrees/loop-<slug>` na raiz do projeto-alvo, criada de `origin/<default>`.
- Estado em `docs/loops/<slug>/`: `contrato.md`, `plano.md`, `estado.md`, `injecoes.md` (+ `.quadro.json` quando o espelho GitHub estiver ligado).
- Colunas do quadro, exatamente: `pendente`, `executando`, `verificando`, `revisando`, `aceita`, `bloqueada`, `estagnada`.
- Estados terminais, exatamente: `sucesso`, `no-op`, `bloqueado`, `estagnado`, `esgotado`.
- Níveis de modelo: `haiku`, `sonnet`, `opus`. Revisor nunca abaixo do implementador; revisor de qualidade sempre `opus`.
- Freios: 3 rodadas por tarefa; 2 rodadas sem progresso → sobe 1 nível (uma vez); 2 rodadas de revisão final; depois `estagnado`.
- Loop nunca: push na branch principal, merge, deploy, release, escrita fora da worktree.
- Falha do GitHub nunca para o loop: marca `quadro: dessincronizado`.
- Commits terminam com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. `inject` sem loop ativo, com dois loops e sem slug, ou com slug inexistente → erro claro, nada gravado (Task 3).
2. `inject` com texto de várias linhas ou com `|`/`#` → uma única entrada, linhas seguintes indentadas, conteúdo preservado (Task 3).
3. `quadro-sync` com `gh` falhando → saída 0, `quadro: dessincronizado`; próximo sync bem-sucedido volta a `github` (Task 4).
4. `estado.md` editado à mão com status desconhecido ou linha de quadro quebrada → erro com número da linha, nunca ignorar em silêncio (Task 2).
5. `init` com branch ou worktree já existente → recusa sem tocar em nada (Task 2).

### Task 4: `quadro-sync` (espelho GitHub Projects)

**Files:**
- Create: `scripts/lib/gh.mjs`, `test/quadro-sync.test.mjs`, `test/fixtures/fake-gh.mjs`
- Modify: `scripts/loop-eng.mjs`

**Desenho decidido:** um Project por loop, título `loop-eng: <slug>`, owner `@me`. Campo single-select **`Etapa`** criado pelo CLI com as 7 colunas (o campo `Status` padrão do GitHub não tem opções editáveis via `gh`). Tarefa = item de rascunho com título `<id> [<nivel>] r<rodada> — <titulo>`; corpo = vereditos + commit. IDs guardados em `docs/loops/<slug>/.quadro.json`: `{number, projectId, fieldId, options: {<status>: <optionId>}, items: {<tarefaId>: <itemId>}}`. A visão em colunas agrupada por `Etapa` é configurada uma vez pelo usuário na UI (o `gh` não cria views) — o CLI imprime esse aviso na criação.

**Interfaces:**
- Consumes: `resolveLoop`, `parseEstado`, `serializeEstado`.
- Produces (`gh.mjs`): `runGh(args: string[]): string` — se `LOOP_ENG_GH_FAKE` definido, `execFileSync(process.execPath, [fake, ...args])`; senão `execFileSync('gh', args)`; sempre com `--format json` quando o comando aceita.
- Produces (CLI): `quadro-sync [slug]` — se `quadro: off`, não faz nada (exit 0). Senão: cria Project/campo se `.quadro.json` não existe (`gh project create`, `gh project view --format json` p/ `id`, `gh project field-create --data-type SINGLE_SELECT --single-select-options <7 colunas>`, `gh project field-list`), cria itens que faltam (`gh project item-create`), atualiza título/corpo/etapa de todos (`gh project item-edit`). Sucesso → `quadro: github`, `project: <url>`. Qualquer falha do `gh` → `quadro: dessincronizado`, mensagem no stderr, **exit 0**. Commita `chore(loop): quadro` se `estado.md` ou `.quadro.json` mudou.

  - segundo sync após mudar T1 para `aceita`: nenhum `create`; `item-edit` de T1 com o optionId de `aceita`.
  - sync com `FAKE_GH_FAIL=1` → exit 0, `quadro: dessincronizado`; sync seguinte sem falha → `quadro: github`.
  - `quadro: off` → fake-gh nunca chamado.
